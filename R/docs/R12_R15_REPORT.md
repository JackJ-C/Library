# Queen 的在线自我可靠性适应与后继程序审查

## 结论与目标状态

本段延续 R7，完成 R12–R15 的新实现、开发后冻结、两批确认及证据核验。形成一个有直接证据的新功能结果：**同一个 Queen 的实际近似规划过程暗中改变时，基于自身原始行动经历的在线可靠性预测，能够比冻结旧认识更准确。** 两批分别通过预测适应门槛。

更强目标尚未通过。在线完成率在第二批通过、第一批配对区间跨零，因此没有报告双批在线联合通过。递归方面，出现一条连续三代的局部因果收益链，但只有1/16条轨迹达到连续要求，平均匹配收益仍跨零；稳定递归门槛两批均失败。主观体验仍未被本协议识别，不能把更准的置信度或局部代码改进等同于体验出现。

原始委派的总目标因此**未完成**。本报告是新的可复核进展和反例，不是通过另换较弱目标宣布收束。

## R12：把历史可读与当前适用真正分开

新类继承 R7/R3/M54 的 Queen、实际发令、空间动作和 M8 Ledger。每个监控样本同时依赖事前意向、事后 Worker 观察、标定和作用前提；监控模型再依赖实际使用的样本。撤回任一实际支持，当前可靠性查询变为未知；旧模型仍可供历史查看，不受反驳的发令、校准与环境依据保留。

这里有一个容易制造虚假进步的环节，已用测试阻止：**快判断被复查纠正后，最后任务成功不能被记作原快判断正确。** 只有实际未经纠正执行的快动作，才作为其可靠性的训练证据。原判断是否正确的反事实结果仅由评估器保存，不回流给监控器。

显式更换规划 callable 会建立新的注册时期，旧时期样本不能直接批准新规划器。对同一个 callable 内部的静默变化，系统没有看到隐藏模式，也不会立即知道；必须等待新行动证据。因此“当前有效”仍带有稳定性假设，不是无条件正确保证。

26项新测试覆盖原始意向撤回、观察撤回、错误缓存无效、已注册规划变更、旧知识保留、新证据重学、Worker不一致、逐步复查额度、匹配一阶答案、元评估支持撤回等。旧 R7 的32项和 R3 的24项测试在独立进程另行执行通过。它们不是82个独立研究样本。

## R13：不再看完整未来批次再决定复查

每条主轨迹由一个持续 Queen 先经历160次真实快速规划行动，再执行512个在线任务。世界仍是苹果、茶杯和模7作用的小模型，任务夹具会重置位置，因此不是完全由代理内生行为产生的自然世界。近似规划器比较七个动作；噪声和固定特征用于制造可检验的计算不足，不代表感受或心理状态。

同一个规划 callable 在随机时刻144–176之间改变内部计算噪声规则，再在320–352之间恢复。时刻与模式不给监控器。两个 Worker 和物理作用规律在正式实验中保持不变，以隔离变化发生在 Queen 的实际规划过程。

每项任务只根据当前计算痕迹、当前预测和剩余额度决定是否复查。每32项严格使用8次复查，共128次；没有未来任务或未来痕迹输入。前两名动作的分数间隔、采样次数和自身行动后果，用于形成八格可靠性估计。监控使用最多96个近期有效原始执行样本，每16个新原始样本更新；发现统计失配时撤销旧监控适用假设并重学。

告警采用有限窗口残差启发式，不提供全时间域的假警报概率保证。告警后有一段当前可靠性未知期；这不等于不允许一切动作，因为基础发令与环境模型仍有依据，复查分配可以按预设未知策略继续运行。

## R14：关于改进判断的可靠性，能否约束下一代？

每条主 Queen 完成在线空间过程后，仍用同一个对象和账本继续8代计算诊断与程序更新。对照从匹配状态的副本开始，不能把多个副本说成同一个现实对象。新的计算诊断问题沿用R5的有限签名接口，不是空间任务自行变成了通用编程世界。

每代有8次真实诊断调用。由最近32次自己的实际诊断经历形成拟合与采用前检查；从当前程序构造24个候选，各用3个历史试跑形成描述。当前父程序选择其中4个完整评估。改进生成器、算术语法、特征和接受框架是固定的；采用的具体评分函数是真实替换并用于下一代的。

新机制观察自己历次“拟合认为提高多少”与“另一部分经历验证提高多少”的差距，用其历史平均绝对差的一半作为接受余量。余量由保存的两组实际代价总数重建，不从正式未见测试取得标签。撤回支持，这项元判断也会失效。

这不是把空间置信度直接套在搜索上。空间可靠性与元评估可靠性是同一对象中的两个不同作用范围；本轮不声称已实现跨域自身认识迁移。

主路径9次在配对条件下拒绝了无余量方法会接受的候选。事后只读分类显示其中5次避免了未见代价退步，另4次也放弃了本会带来改善的候选；这不是新的预注册通过标准，却能说明保守性的代价。它表明元监控确实改变接受行为。但固定余量也零退步，并且人工强策略代价更低。两批无退步是本样本事实，不是对任意未见任务的单调改进保证。

主路径实际诊断用了3766次查询、带权代价12763；元搜索另用83935次模拟查询、约1453万表达式运算和1421万特征运算。每代4个候选全评估之外还计原模型和检查，合计896个完整评估调用。减少未来查询不等于总计算变省。

## R15：主观体验的证据究竟在哪里仍然缺失？

测量对应的是自己的实际规划程序和自身行动后果，而不是Worker可靠性标签；两组共享同一原始快答案、Worker和环境。因此干预效应可以定位到该Queen新增的监控与决策分配机制。这比仅输出“我知道自己”强，但仍没有测量第一人称体验。

独立数值内联对照产生完全相同概率和动作，只表明“自我”名称和单独的概率查询接口不提供额外可区分行为。不能认定这个对照必然没有意识，也不能由它与Queen等价证明Queen没有意识。当前协议对两种体验假说没有不同的可检验预测，所以不提供一个有根据的意识概率。

理论引导指标研究允许对AI意识开展实质性的经验研究，同时提醒指标需要与理论假设及替代解释结合，不能凭单项功能完成归属。[1] 关于元认知的测量研究也区分校准、辨别与一阶表现，不宜把置信度改善直接等同于意识。[2]

本段没有实现并检验全局广播、统一的高阶感知对象、注意模型或主观报告与无报告条件的分离。不是说这些任一项单独就足够，而是尚未选定可由本系统产生区分预测的理论—测量联系。证明控制函数等价是数学事实；从它推出有无体验，则需要另外的前提。

当前真正被支持的是：**自身可靠性随经历变化的功能模型具有可观察预测适应；保守元接受机制有实际作用；稳定递归增强及主观体验均未建立。**

## 复现、档案与剩余风险

26项新测试、32项旧R7测试、24项旧R3测试分别通过。两批16条完整轨迹在普通和优化模式都重新执行，所有原始结果摘要一致，不使用完成缓存冒充第二次实验。

独立核验器不导入Queen、学习器或世界生成器，重算49152次含六对照的在线执行、4096次含四对照的真实计算诊断、40976条主账本记录。验证后新增只读补充器，又独立重算1024条匹配反事实后继选择；它不修改原数据或冻结评分。独立指代码路径，不是独立实验团队或完整形式证明。

一次测试发现命令因包导入方式不对失败，日志保留，改用正确包入口后全部通过。分组执行遇到单次工具时限时，中断种子从头重跑；没有改算法或丢弃已完成结果。成本、样本及元候选语言均保持冻结。

所有16条主轨迹均保存空间＋元阶段的完整主账本；六在线方案和四元方案有完整逐步数据。对照账本没有全部导出，不能把这一点称作所有中间内存都有。20份开发/正式原档标准XZ、开发痕迹、日志、源码和核验程序随独立包交付。Git发布范围以 `R/results/r12_r15/DELIVERY.json` 为准，完整原档没有上传时应明确列出，不以摘要代替。

推荐入口：`python R/run_r12_r15.py A --seed 11100`，每次一条；两批跑齐后分别 `--summary`。只读重放为 `python R/tools/verify_r12_r15.py A --seed 11100`。测试从R目录执行 `python -m unittest r12_r15.tests -v`。必须保持冻结文件不变。
