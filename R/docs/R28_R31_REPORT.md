## 因果空间究竟是什么

一个点是b=(allocator AST, scale)。固定某一代的任务候选、已实际查询辨识的有限机制、初始化与运行预算后，替换这个点并实际执行模拟，取得后续任务诊断的查询/回复轨迹：

phi_(t,j)(b) = Trace(Exec(do(allocator=b), context_(t,j)))。

d_t(b,b') = sum_(j in J_t) 1[phi_(t,j)(b) != phi_(t,j)(b')] / |J_t|。

J_t是当前能拆分已观察行为等价类的见证列。第一列建立范围；新列只有进一步分裂当前类才保留。距离在候选上是伪度量，在已观察等价类上是度量。所有原程序保留；当前零距离不等于所有未来条件等价。每一代的空间重新由当代候选与最多三列pilot见证形成，不是跨代连续生长的内在流形。

这里的干预是在声明模拟器内实际替换程序执行，不是单凭相关性恢复开放世界因果。旧Ledger的deps仍是证明依赖，不自动成为世界因果DAG。源码继承R3 Queen→M54 Queen→M8 Ledger，使用未改动R23 allocator与R4任务解释器；不是缺失R24—R27代码的复现。

Queen构造了具体坐标及局部等价类；坐标提取规则、Hamming形式、语法、目标、解释器、候选生成器和验收器由研究者提供。本轮没有证明Queen创造了这些元规则，也没有直接证明它学会主动选择最有信息量的新干预。

## 固定实验与完整组合边界

正式A=43100—43107，B=44100—44107；每条6代、8个allocator/scale候选、6个任务候选、内层12次逻辑测量。每个案例16种机制；每块4个拟合案例和2个检查案例；最多6块历史、3块pilot，每个分支全检2个额外候选。

所有候选及scale、历史视图、任务候选和影子提议先写入账本，再取得4块新采用经历。采用AST与scale整体，不在采用后偷偷改变scale；随后实际选择并绑定下一代使用的任务程序。6块评估器专用测试随后产生，不送回Queen。

必须保留与原统一模型的区别：本轮是离线探索性替换，有限采用银行平均改善超过0.002即可采用。原保守总体风险证书全部为UNKNOWN，严格执行该证书时不能部署。这里没有证明未来风险不退步，更没有完整实现原Theta=(p,a,c,m,eta)的全部状态联合认证；任务选择、历史更新和环境范围仍按固定协议处理。

## 两条可复查的失败

### 更新确实改善当前任务，却不构成递归增强

A种子43101，第3代（从0编号）：已有上一代采用，本代把(visits-uncert, scale=2)更新为(constant 1, scale=0.5)。相对父代的测试改善为0.002314815；但前代和初始改进器在同候选、同经历和同逻辑额度下选出的后继，比它好0.027777778。因此前一次改进没有帮助这一次选得更好，不能算严格递归环节。

96代中只有这一次连续实际采用。这个计数表明递归链机会很少，不证明“只要放宽门槛就会成功”。

### 新鲜采用证据仍可能误采用

B种子44101，第2代：从(mean-uncert, scale=1)更新为(constant -1, scale=2)。新采用银行显示改善0.003472222而获准实验性替换；独立测试反而退步0.002893519。它直接反驳“只要新鲜证据和空间都有，就能保证采用正确”。

完整9次更新记录见results/r28_r31/ADOPTION_EVENTS.json；这属于结果固定后的诊断，不回流训练。

## 同信息对照与新增反例

图重建从原始证据节点与关系重新取得相同响应，96代主路线提议全部相同；16条主轨迹另以普通JSON读取方式完整重跑，整个结果对象的JSON值一致。重复执行不增加科学样本。这不支持空间容器本身优于同信息图或普通日志；真正待检的是信息使用策略。

新增构造反例：三个程序的三列响应分别A=(0,0,1)、B=(0,1,1)、C=(0,1,2)。按A,B,C取证时保留A,B，前两程序距离0.5；按C,A,B取证时只保留C，距离为1。等价类相同，距离却改变。原“已选坐标倒序不改变距离”测试没有覆盖“取证顺序改变坐标选择”。冻结代码不改；反例和新测试原样交付。当前几何是依赖取证顺序的见证几何，不是已识别的内在几何。

此外，几何只记录有限检查轨迹，未编码所有未来探索行为。异于父代可以更好、可以更坏；当前0.025×novelty启发项及优先新类，并没有因此获得收益保证。不能把距离大直接叫进化。

## 复现

在完整包的R目录执行：

```bash
python -m r28_r31.tests
python -m r28_r31.run A --output results/recompute_A
python -m r28_r31.run B --output results/recompute_B
python tools/audit_r31.py --batch A --linkage-only
python tools/audit_r31.py --batch B --linkage-only
python tools/test_audit_r31.py
python tools/summarize_r31.py
```

原runner默认不覆盖现存原档。linkage-only明确复用已核对SHA的原runner算术回执；省略该选项会重新做算术与关联核验。tools中的新增内容属于事后只读工具，不在原14项冻结集合内，其自身源码hash在交付清单中。

## 推进点与未完成强主张

完成了“证据图→可执行干预响应→可修订局部空间→实际候选选择”的接线，并用正反干预确认它不是装饰性坐标。但从“空间可构造”到“空间稳定有益”，以及从“任务后继更好”到“改进机制帮助产生下一次更好”，两步仍没有通过。
