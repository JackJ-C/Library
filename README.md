# Library：希珀塞莱妮娅的图书馆实验

> 让变化中的系统进入历史切片，重新观察过去的行动与判断，并检验：这些证据现在还支持什么改变？

## 当前进展：M0–M7

本仓库从《星际穿越》图书馆的直觉出发：Queen 能重新观察过去的自己和整个系统。此前的“德罗斯特效应”是对此的近似表达。它不是普通问答记忆库，也不预设 Transformer、语言模型或三维存储。

**目前形成了一个有条件证明和有限全集实验支持的理论原型：版本—目标约束的再观察。** 已完成 M1–M7 的限定实验，不代表已经造出可无限自主进化的 Queen，也没有建立全球首创或现实复杂任务上的优势。

本轮只在 `JackJ-C/Library` 中进行。没有连接希珀塞莱妮娅主系统、修改其他仓库、启用 GitHub Actions 或调用付费训练。

## 先读这三项

[研究总报告](docs/RESEARCH_REPORT.md) 汇总实际结果与复现方式；[理论正文](docs/LIBRARY_THEORY.md) 给出定义、证明和已有研究交集；[M7 目标冲突报告](docs/M7_REPORT.md) 解释为什么“修好内部”有时会让外部表现变差。

## 最重要的发现

系统不一定要先知道全部故障，才知道怎样修正。在固定的 256 个二值世界中，4 次观察即可确定内部净校正，而完整区分所有内部与环境参数需要 8 次；停止修复诊断时仍有 16 个世界不能区分，但要求的校正相同。

然而，内部正确不等于整体进化。256 个内部校正都通过本阶段固定目标，但在自然环境下，48 个世界的平均表现下降；若要求保住每一个原有成功案例，则有 144 个世界出现退化。穷举全部四种允许修改后，这 144 个世界仍无解：两个目标在该修改范围内不可兼顾。

还有一个必须保留的负结果：**同信息、同算法的普通完整日志与 Library 全部打平。** 当前证据不支持“图书馆存储形式本身更智能”，也不支持几何空间或递归层数天然带来优势。

## 一个核心关系

设 H(v,E) 是与版本 v 及当前证据 E 相容的非空候选集合，A_C(h) 是候选世界 h 中满足固定合同 C 的修改集合：

$$K(v,E,C)=\bigcap_{h\in H(v,E)}A_C(h).$$

K 非空，才有每个兼容解释都支持的修改。这个保证依赖真世界在候选集合内、证据与干预可信、执行正确以及目标明确。K 为空时应区分：证据不足、目标冲突、允许修改太少，还是模型本身错了；不能统称“再多想一会儿就能进化”。

这是研究中的工作框架，不将基础集合论或已有主动诊断思想改名冒充新数学。

## Queen 与 Worker：读取不等于亲历

Worker 的行动保持 Worker 来源；Queen 的读取和判断产生自己的新记录。后来的 Queen 能检查自己此前怎样观察系统，但不能把 Worker 的历史改写成自己的亲历。

版本沿袭、观察来源、历史适用性也不是同一件事。M5 检验的是变化后哪些约束还能使用，不是哲学身份或自我意识。

## 本地复现

在仓库根目录运行，只有 Python 标准库，不下载模型，不联网：

```bash
python3 tools/verify.py
python3 run_m1_m6.py
python3 run_m7.py
```

本轮实际环境为 CPython 3.13.5。新增 23 项测试通过；主实验和 M7 均以普通与 `-O` 优化模式实际复跑，产生相同结果内容摘要。其他 Python 版本未实测。

为了完整保留原始记录并缩小仓库，四份本轮原记录收在 `results/evidence_bundle.tar.xz`，清单是 `results/evidence_manifest.json`。验证器会直接读取包内 JSON，不要求手工解包。重新运行实验会在 `results/runs/` 生成对应 `.json.gz`，不覆盖不同摘要的旧档。

摘要入口：[主实验](results/m1_m6_summary.json)、[M7](results/m7_summary.json)、[验证记录](results/verification.json)。原记录包含逐世界数据、随机种子成本、版本变化行和完整自动切片示例。

冻结实验合同与协议分别保留在 `docs/M1_M6_CONTRACT.md`、`docs/M1_M6_PROTOCOL.md`、`docs/M7_CONTRACT.md`。探索性补充、源码打包修正和来源局限在总报告中说明，不根据成绩改写旧合同。
