# 从手写元规则到生成高阶构造器与反馈搜索律

## 结论

M25–M28 补上了一个比 M24 更具体的实现缺口：本轮没有把“减去原点值”的完整构造函数或完整反馈搜索公式放进合成器，而是让统一的算术程序枚举器根据性质和反例生成它们的函数体。生成的一个构造器随后成为合成下一个构造器时可调用的既有程序；生成的搜索函数则依据两次试算的数值提出新候选，不再只是重排已有搜索分支。

这支持“给定基础语义与性质任务，系统能生成两类元程序并使用它们”的结论。不支持“基础枚举器、性质目标、所有搜索原理都由系统自行创造”。合成出来的搜索公式与经典割线/逆线性插值等价，不是新的数学公式；强手写基线与本方案打平。

## M25：究竟改变了哪一层

基线为 `320b4a89a98b44ef78b690774661b0e90edf439b`。回读 `library_m21/synthesis.py` 后，确认旧 `learn_normalized_macros` 手写了输出归一化，`learn_plan` 只枚举分支排列。本轮没有重跑旧阶段，旧数字不算新增证据。

三层现在分别是：任务程序；产生工具的高阶构造器及反馈搜索提案函数；组织发现过程的枚举器、解释器、性质合同和安装器。本轮生成的是第二层的完整函数体。第三层仍然固定。这不是通过给一个手写函数换名字来扩大“自主”的定义。

搜索模块 `library_m25/language.py` 只有变量、0/1、加减乘除、通用候选枚举及编译。它不导入评估模块或代数验证模块，也没有正确元规则的 AST 常量。强手写对照只在评估层；单元测试把两个参考函数替换成会立即报错的桩，元程序发现仍能完成。

不过，性质目标、观察寄存器与锚点 0/1 都是研究者设计的先验；稀疏算术语言也针对这个有限问题。不能把这些目标规范的提供冒充系统自主发现了“应该研究什么”。

## M26：生成“程序进去、工具出来”的函数

第一课程只规定三项性质：给输入函数加常数不应改变产物；产物在 0 为零；原本在 0 为零的函数应保持不变。没有提供实现公式。

程序搜索实际经历 `0`、`1-x` 两个被反例推翻的候选，随后生成：

```python
def construct(f):
    def tool(x):
        return f(x) - f(0)
    return tool
```

第二课程要求对任意仿射干扰保持不变，并保留在 0、1 都为零的函数。枚举器可以通用地调用刚刚学得的构造器。它先后提出三个被反例否定的候选，最后生成：

```python
def construct(f):
    prior = previous(f)
    def tool(x):
        return prior(x) - x * prior(1)
    return tool
```

这里的 `previous` 是第一课程实际生成的函数，不是评估器给的正确模板。展开后为 `f(x)-f(0)-x*(f(1)-f(0))`。

第一、第二构造器分别尝试 58、1394 个候选，发生 2、3 次真正的反驳。冻结之后，在种子100–107的验证集及1000–1063的挑战集检查；两个挑战分别含4288、4352条性质关系，全部通过。单元测试与后续组合实验还使用分段、奇偶、高次函数。

这是真正的高阶类型：它接收一个可执行函数，返回另一个可执行函数。它不是只把一个固定任务算对，也不是从12个完整程序中挑选。

### 比有限测试更强的部分

独立验证器把实际生成的 AST 展开成以 `X,F,F0,F1,A,B` 为变量的稀疏多项式，核对平移/仿射不变性、锚点和保持性恒等式。七项差式全部化为零。

因此，这些性质不只在训练函数中成立：在声明的精确整数算术、稳定函数调用语义下，它们对任意整数函数成立。这个保证不是“目标任务任意复杂都能求解”，而是这两个构造器满足其指定性质。解释器或函数调用不可信时，保证不再适用。

## M27：生成利用数值反馈的搜索公式

输入是此前两次试算的候选参数和实际残差 `(p0,p1,r0,r1)`。枚举器只收到性质检查的成败与反例，不收到正确根、斜率、任务源码或目标公式作为标签。

第一候选 `-p1` 在初始例子上碰巧成立，随后被新案例推翻。最终生成的可执行函数为：

```python
def propose(p0, p1, r0, r1):
    return (p1*r0 - p0*r1) / (r0-r1)
```

实际实现使用 `Fraction`，不是浮点近似。总计尝试15532个候选；12个训练案例和32个独立验证案例通过。生成 AST 代入一般仿射残差后，根的残差分子恒等于零；分母为非零斜率乘两个不同试算位置之差。

这与 M24 的分支排列有本质区别：新函数读取试算的数值关系，计算一个此前没有试过的参数。它改变了提案计算，而不是仅改变枚举次序。

但搜索对象是任务程序的一个整数系数，不是任意 AST 搜索的完整算法。实际发现这条提案律的外层枚举器没有自行改写。公式也等价于已有的割线/逆线性插值，不宣称数学首创。[1]

## M28：组合后在未用于学习的新任务上实际运行

冻结两类元程序后，以64个新种子和4个新函数家族生成256个任务。每个任务提供一个带仿射干扰的已有程序，系统用生成构造器制作工具，再用生成搜索律寻找该工具的整数系数，最后把结果实际绑定到同一 Queen 实例的任务程序。

任务族含三次、四次、绝对值组合以及带整除/奇偶的函数。最终目标与已有程序之间的结构关系、系数范围及双锚点重组方式是明确先验。目标黑箱的参数和源码不进入元程序学习。

| 路径 | 采用且全部未见检查正确 | 候选程序试算次数 | 外部目标观测点数 |
| --- | ---: | ---: | ---: |
| 生成构造器＋生成搜索律 | 256/256 | 761 | 1536 |
| 生成构造器＋顺序枚举 | 256/256 | 8708 | 1536 |
| 生成构造器＋二分 | 256/256 | 1802 | 1536 |
| 强手写构造器＋插值 | 256/256 | 761 | 1536 |
| 同信息 JSON 测量记录 | 256/256 | 761 | 1536 |
| 去掉构造器、保留生成搜索律 | 0/256 采用 | 522 | 798 |
| 两者都禁用，使用原程序＋枚举 | 0/256 采用 | 15836 | 798 |
| 只有两个初始试算，不再搜索 | 7/256 | 512 | 789 |

主路径的6912个未见输入全部正确，旧的零输出程序此前成功的案例无退化。每个主任务测量0、1、一个诊断点及三个采用前验证点，因此剩27个输入才计为未见。拒绝组没有被算成错误部署；它们保留旧程序且没有获得许可。

禁用构造器的对照只说明在固定重组任务族下，该表示变换有用；不能据此证明其他不使用构造器的完整合成方法都失败。

### 成本不能混算

761对8708是候选程序的试算次数减少91.26%，并不是外部数据查询减少91.26%。目标测量被缓存，相同任务的所有候选复用相同诊断点，所以主路径和枚举实际都取得1536个外部目标观测点。原工具函数的执行、编译和性质检查也有成本，没有测量或宣称整套系统的墙钟加速。

元学习另消耗16984次候选尝试、17451次性质/反馈检查。这笔成本不能从部署统计中消失。没有提供摊销总成本或通用最优性结论。

## 反证与当前失败

非线性残差任务中，生成提案分别为9/5和16/5，执行后残差非零，不能接受。重复相同残差会产生零分母；旧任务的残差会导向错误新根，真实验证拒绝。单个观察也可以兼容不同根，不能据此保证定位。

隐藏分支只在13触发时，程序仍在采用前检查中通过，并在最终13上出错。错误但一致的外部参照，也能让所有实际输出相对真实目标都错。本轮没有把压力测试反馈回主学习。

证书实际绑定任务、证据、构造器、搜索律、模式与语义版本，函数绑定或上下文变化会使许可无效。五项上下文变化均拒绝。不过，标签“exact-v1”本身不能证明底层解释器真的没有损坏；独立代数检查与错误运行语义仍可不一致。本实现不是恶意进程安全沙箱，也没有排除共享可信基础失效。

## 原创性与完成范围

本轮做到了项目内的新一步：把过去手写的两个元函数体转为运行中生成，并独立核验，再组合执行。没有新增完整规则候选表，也没有在挑战之后改公式。

但是，搜索公式是已知插值；学习程序库、从基本操作搜索学习算法、搜索管理程序自身，都有直接先例。[1–4] 目前不存在同基准优于这些工作的结果。完整原创性评估见理论正文，不以重新发现经典公式声称全球突破。

因此，M25–M28完成的是“有基础语义与目标规范的第二层元程序合成和部署”，不是没有固定基础的无限递归创造。把这次结果说成固定外层合成器也自主产生，将超出证据。
