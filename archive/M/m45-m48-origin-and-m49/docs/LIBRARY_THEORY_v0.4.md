# Library v0.4：有界的因果自诊断与可撤销修订

## 摘要

本稿把“Queen 修订对系统的解释”推进到一个更直接的命题：在可分离的观察接口、公开任务规范和可信元审查核下，Queen 能否区分自己实际执行的判断程序与 Worker 测量机制的故障，并只修改需要修改的位置？

答案在这里规定的有限程序族中为是。证据不只是一句归因标签，而是盲故障、历史行为、真实函数绑定、按组件干预、未来任务和不误改正常组件的组合。M13 穷举 2304 次审查，定位、修改位置和未来行为一致。M14 同时给出模型族外和元核失效反例，M12 发现并用新适配器处理了旧实现中的证书生命周期漏洞。

“有界”不是修辞：可变判断程序、固定审查核、任务规范和可信记录必须分开。当前没有证明整个 Queen 的全部认知过程都能在无外部依据时自证，也没有证明任意未知程序故障可修。以下命题是本研究框架中的条件推导；元认知循环、主动诊断和自动程序修复已有先例，不宣称它们的优先权。[1–5]

## 1. 什么才算本实验中的“自身”？

把实际运行的代理写为 A=(K,J,W,L,C)。J 是 Queen 当前用于执行判断的程序；K 是维护候选、检查证据与批准修订的元核；W 是独立 Worker 的测量/解码路径；L 是历史记录；C 是固定任务规范。

本实验以控制归属定义自身的操作边界：J 被当前 Queen 实例的 `decide` 调用，产生本实例的历史判断，并在修订之后继续为同一实例的未来任务服务。修订 J 是本实验所说的自身判断机制修复；修订 W 是对 Worker 的校准。二者不是根据一个字符串名字判定，而是通过真实调用和写入位置区分。

这仍是一项结构假设，不是系统从无标签经历中发现了哲学身份。谁拥有实例、记录是否真实，以及 K 的可信性由执行环境保证。把另一个外部模型命名为 Queen 不能自动满足本定义；反过来，仅把一个调试器放进同一 Python 类，也不足以证明主体意识。

M13 的关键不止是“同一个对象名”，而是：历史由真正有错的 J 产生；归因不接收初始故障标签；批准修改实际改变 J；未来仍执行 J；W 正常时不被改；对照干预显示改另一处不能替代这项修复。

## 2. 四层主张不能混用

第一层是来源记录：知道哪条记录标作 Queen 或 Worker。第二层是模型修订：改变 Queen 对系统的预测模型。第三层是本稿检验的局部自诊断：把真实判断程序 J 当作可能出错的对象，与 W 分别诊断和修改。第四层则是审查核 K 及其评价基础也能自主检查和修复。

M0–M11 主要提供前两层的证据。M13 补第三层。当前原型不具备第四层；M14 直接损坏 K 时产生错误自信和失败，不能用第三层通过掩盖这个区别。

## 3. 故障定位首先是可区分性问题

设有限机制族 H 中的一个世界 h 包括实际 J 与 W 的状态。固定合同 C 下的故障位置为 z(h)，可取正常、自身、Worker、两者。Q 是允许进行的观察和干预集合；历史是实际观察的一部分，而不是无限次重复计数的证据。

定义 h≈h'：两者对全部允许查询给出相同响应，包括允许读取的自身输入、输出和读取集。

**命题 1：定位充分性。** 在确定性、审查期间状态稳定、真实机制在 H 中、查询和记录可信的条件下，仅凭 Q 保证正确定位 z，当且仅当每个观测等价类中的 z 都相同。

必要性：若某个等价类包含不同位置的故障，任何自适应查询在这些世界中都得到同一响应、采取同一路径，最后的确定性标签无法同时正确。随机化也不能为每个世界提供概率 1 的正确定位。

充分性：执行有限集合 Q 的全部查询，找到真实世界所在的观测等价类；若其故障位置一致，则输出该位置。这个证明不保证有效率；具体策略可以提前停止，但仍需保留兼容集合。

这是一项基础可识别性论证，与已有主动诊断和决策区域研究有交集。[2] 它的重要性在于说明“读到了自己的历史”和“历史足够定位自己的不足”不同。

## 4. 为什么只看端到端结果不够？

两个简单世界分别为 W(x)=x、J(y)=y+7，以及 W(x)=x+7、J(y)=y。对任何 x，最终输出都是 x+7，而故障位置相反。只允许最终输出查询时，命题 1 的条件不成立。源码附有 33 点的有限核验，恒等关系则由代数直接成立。

将已知输入直接交给 J，以及将已知标定值直接交给 W，可得到不同响应。新增的是观察分辨能力，不是“多想了几遍”。诚实的自身输入—输出切片可以提供类似分离信息，但其可信来源必须说明。

同时，无法定位不一定无法提高成绩：盲目重置两边有时也能修好任务。这就是为什么单看修复后的总分，不能证明 Queen 已经区分了自己与 Worker。

## 5. 修改证书要约束位置，而不只约束分数

延续 v0.3 的共同修改集合。对每个兼容机制 h，令 A_C(h) 是满足固定合同的修改集合；合同可以同时要求任务正确、保持历史成功，以及不改动已经正常的组件。修改 u 的实际写入所属位置记为 B(u)。

$$K(E,C)=\bigcap_{h\in H(E)} A_C(h).$$

空候选集合表示模型或证据不一致，不批准任意修改。候选非空但 K 为空，表示当前没有共同可接受的方案；这可能是定位信息不足、目标冲突或修改范围不够。

**命题 2：带位置约束的修改充分性。** 当真实机制属于 H(E)、执行后果和合同判定正确时，对所有兼容机制都满足任务及位置约束的修改存在，当且仅当 K 非空。

证明与旧版交集命题相同：交集内的方案在每个兼容机制下合格；交集为空时，任何方案至少在一个未被排除的机制下不合格。新增的是合同语义，而不是声称发明了集合论。

M13 对“正常组件不改”的要求尤其重要。只修自身组实际保留 Worker 的解码状态；只修 Worker 组保留 Queen 判断函数的绑定；正常组无修改；联合组分别改变两处。这里的最小性只针对已声明的三个代码槽位和 Worker 校准位置，不是任意源码距离的全局最短修复。

## 6. 具体算法为什么不需要故障标签？

Queen 的候选语法包含两个主体过滤方式、两个时期选择方式及三个聚合操作，共 12 种实际可执行程序。每个候选被独立解释器重放于保存的原始输入；只有输出及读取集与实际执行吻合的候选保留。故障掩码从这些候选相对于公开任务合同的差异推得，不读取当前函数的编号或指纹。

若兼容候选不能一致确定需要修订的槽位，就选择会区分候选的自身探测；若证据与所有候选不符，则拒绝。Worker 通过已知输入 -4、0、9 的实际测量检查非零仿射假设，推导逆校准。随后，Queen 候选在分开的批次上验证，Worker 校准在 37、-23 上验证，通过后才采用。

“同一规范下生成一个正确程序”在本任务里不困难，规范也不是学习器发明的。因此成功不证明系统发明了新算法。实验的主要区分在于，它是否以证据识别实际错误位置、只修改对应机制，并在未用于选择的任务上保持效果。

函数指纹用于检查交付和实际绑定，不用于判断某个函数是否有错。指纹伪装测试表明，本实现没有靠指纹查表获得故障标签。

## 7. 有限实验中的分离性与修复

本任务的一个完整批次包含目标主体的两个时期，以及另一个主体的更早和更晚时期。四种过滤—时期组合选出四个不同的记录集合。每个集合的数值互异，中位数、最小值和最大值也不同。因此在主族的非零测量斜率条件下，一个完整的自身输入、输出和读取集就能区分 12 种程序。

这解释了为什么去掉旧历史后一个丰富的新探测已足够，而不是算法得到了神秘的常数复杂度。主实验先存四个任务的记录，实际上包含冗余分离信息。对一般程序、缺失读取集或不充分的探测，不能照搬此结论。

Worker 的两个不同标定点确定仿射映射，第三点检查一致性；有限三个点仍不能证明任意未知函数在所有输入上仿射。若实际路径处于该族且斜率非零，逆映射确实恢复输入。Queen 选择正确主体/时期后，中位数在未来批次上满足规范。

2304 次实验覆盖两个合同、全部 144 个 Queen/Worker 组合和八个布局种子。176 次仅自身故障、176 次仅 Worker 故障、1936 次联合故障及 16 次正常全部定位正确。73,728 个机制—未来输入检查全部正确，没有正常组件被误改。单方修复在联合组没有一例完成全部未来任务。

这是可控、可重复、角色明确的局部自诊断证据；不是 2304 种自然故障，也不是对任意未知程序的泛化保证。未来输入改变了名称、大小、数值和时期，但没有改变主要错误语法或可信观察条件。

## 8. 报错不是撤销证书

M12 对旧版读者得到一个具体反例：全域覆盖后出现相反的重复观测，接口抛出异常，却没有清除全域许可。捕获异常的调用者仍能取得 True。

**命题 3：失败关闭不变量。** 若证书依赖的假设 γ 已被一次可信观测否定，则任何保持原条件的当前许可查询都不能继续返回有效，除非已有新的独立证明替代该依据。抛出异常本身不能满足这个不变量，状态必须同步变更或许可查询必须重新检查。

新适配器将矛盾观测留档、沿证明依赖撤销当前假设、设置失败状态后才报错。旧记录不删除；一致重复不会撤销。这沿用 v0.3 对历史引用与证明依赖的区分。本轮验证了全部 256 张三变量表各一条矛盾观测，但没有声称实现了通用逻辑证明核。

撤销也不自动定位原因。矛盾可能来自 Worker 变化、噪声或记录污染；在进一步调查前停止批准，比继续使用旧证书更符合原条件。

## 9. 同样的信息，不会因为换容器而自动更聪明

**命题 4：信息等价对照。** 若两种存储在当前允许的接口上提供相同的完整记录，执行相同的确定性诊断、查询及修改算法，则其决定相同。证明是对每一步输入与状态转移作归纳。该命题不要求两种容器具有相同的读取耗时或空间成本。

本轮同信息 JSON 序列日志对照与原输入逐项一致。它是序列化等价性检查，不是独立强推理算法之间的竞赛，也没有测出空间布局的优势。去掉自身证据的实验则改变了信息条件，不能被用来证明特殊存储介质更强。

图书馆在本框架中的作用，是让依据、所属版本、实际判断和可撤销关系可访问；这一功能可以由多种存储实现。递归引用没有在本轮获得独立性能优势证明。

## 10. 信任边界是理论对象，不是脚注

本原型仍信任：元审查算法 K、任务规范、验证器、原始输入—输出记录，以及 Worker 标定值。审查期间状态固定；当前代码语法和仿射假设覆盖主实验中的真实机制。记录接口并非同进程攻击防护。

M14 的未知 Queen 程序只在未来名称上偏移输出，初始证据和验证都与健康程序相同，系统随后在 32 个挑战中全部失败。非线性 Worker 的标定矛盾则触发拒绝，但未被自动修好。把 K 改成永远报健康，当前系统同样失败；它没有另一个流程去修复这个受损的 K。

这不证明更强的自审查设计永远不可能存在。它准确界定本原型：**固定可信元核对可变自身判断程序的诊断与修复**。把多个检查器无限往上叠，也不能不加假设地把这些外部信任变成已证明事实。

## 11. 完成到什么程度？

本轮完成了一个可检验的有限理论闭合：定义自身的执行边界；说明什么证据能区分自身与他者故障；把修改所属位置纳入许可合同；实现真实函数修订和拒绝；用穷举、干预及未来输入验证；保留无法检测的反例和元核边界。

原问题中“Queen 是否只是发现 Worker 的问题”的缺口，在第三层操作意义上获得了直接肯定证据。第四层的整体自诊断、未知机制的无界发现、真实复杂任务上的独特优势和全球原创性均未证明，不以本稿的完成标记代替它们。

与已有研究的关系也清楚：监控并修改自身决策部件已有元认知循环研究；从观测中取得足够决策信息已有主动诊断；自动生成/验证修订已有程序合成与调试；固定评价标准下的自修改已有形式研究。[1–5] 当前候选贡献是针对 Library 提出的可复现实验规格、明确的自/他定位证据链和反例，而不是宣称这些领域从未存在。
