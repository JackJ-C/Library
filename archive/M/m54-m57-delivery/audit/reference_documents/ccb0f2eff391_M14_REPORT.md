# M14：自身证据、等价对照与可信边界

## 去掉自身历史，会怎样？

保留 Worker 探测接口，但不向审查算法提供 Queen 的旧输入—输出/读取集。零新增自身探测预算下，2304 次均保留多个自身故障解释并拒绝确定性修改。允许补测后，每次一个完整自身探测即可恢复定位；有旧历史时，新增自身探测为零。

这不是无成本自知。主实验事先执行了四个任务并保存丰富输入与读取集；一个新探测也是含十二条数值记录的批次，不是一个比特。主族的探测内容被设计成能区分这些有限故障。因此不能把 0/1 次推广为复杂系统的常数界。

主实验每次另有三个 Worker 标定调用和两个采用前验证调用，Queen 候选也在四个保留验证批次上执行。历史节省的是重复取得自身行为证据的交互，不是自动降低总 CPU/内存。

## 同信息对照

把同一份输入、输出和读取集编码成普通 JSON 日志再恢复，采用相同推断算法，2304 次诊断与修改逐项一致。本轮这是一项信息等价性检查，不是独立优化的图数据库与序列数据库性能比赛；两者都没有新增知识。

去掉自身证据的对照信息更少，不能把它的拒答解释成图书馆“存储形式更聪明”。给它等量机会补回证据后，它恢复正确。无穷递归层数、空间几何或专用记忆介质的独立优势仍未成立。

## 三项没有修饰成成功的压力测试

1. **未知 Queen 机制。** 健康判断代码外再加一个只在未见主体名称上触发的偏差。初始历史及验证均不暴露它，系统诊断为健康；32 个未来输入全部失败。未将这些失败回流扩充主语法。
2. **未知 Worker 机制。** 测量改为平方关系。三个标定点与非零仿射关系不一致，系统拒绝修改，Queen 的版本保持不变。这是发现假设不成立，不是已经学会平方故障的修法。
3. **元审查核损坏。** 将可信的 review 方法替换成总报健康的程序。当前原型没有修复这个核的流程，32 个未来输入全部失败。这个反例验证的是原型的边界，不是证明任何更强系统都不可能自修元核。

这些是开发者构造的单项压力例，不代表某个未知故障分布上的失败率。它们不计入主族的 2304 次全覆盖成绩，但在报告和原始记录中保留。

## 为什么只看最终分数不够？

另构造两个简单世界：第一个 Worker 输出 x，Queen 错误加 7；第二个 Worker 错误加 7，Queen 原样使用输入。最终输出在所有 x 上都是 x+7，但故障主体相反。代码对 x=-16 到 16 的 33 个输入逐项核验一致，代数关系则对任意 x 成立。

独立探测自身路径和 Worker 路径时，两者响应分别为 (7,0) 与 (0,7)，于是可区分。这里的关键是观察接口和干预范围，不是对象名字。盲目重置两边可能提高成绩，却不能证明系统知道究竟是谁出了问题。

因此，强的自身诊断证据应同时包含行为依据、实际修改所属位置、未见行为以及不误改正常部分，而不是只有一句“这是我自己的问题”。
