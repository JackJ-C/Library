回读了主线目录树和文档目录、当前协议及 PR #1 状态；核查三个时期的核心实现和既有报告。对挂载运行包中 11 份关键文件逐字节计算 Git blob 摘要，与远端树核对一致。M8 的两份原始记录经旧验证器解码并通过 SHA-256 核对；重新运行 M8 的 28 项单元测试全部通过。证据见 `results/m12_m15/base_sources_verified.json` 和 `base_tests.log`。

## 结论一：过去的“自身”证据确实有限

M1–M7 的 Queen 信号阶段是模拟器中的参数槽，而诊断算法在外部保持固定。M8 改变的是 PolynomialReader 中的次数、系数及输出校正；处理证据的求解和修订规则本身没有被测试为可诊断、可修复的对象。

因此，旧实验支持“Queen 修改自己持有的解释”，不直接支持“Queen 区分自身判断机制故障与 Worker 故障”。把名字相同的模拟部件当成实际诊断者，会混淆对象。这是证据范围问题，不是说旧计算结果全部错误。

M13 专门补上直接对照：注入故障的函数就是当前 Queen 实例实际调用、产生历史判断、并继续用于未来任务的函数。固定元审查核仍须单独标明，不把它一起算作已能自修。

## 结论二：复现了一个真实的证书生命周期缺陷

对原 `PolynomialReader(3)` 收集八个输出均为零的完整观测，`certify_full_universe()` 返回 True。随后调用 `observe(0,1)`，程序报 `stationarity or noise assumption failed`；捕获异常后再次询问证书，仍返回 True，`failed=False`，撤销节点数为零。

这不需要篡改私有字段。正常调用者处理异常后，仍可能拿到已经失去平稳性依据的许可。原测试只断言出现异常，未检查异常之后的许可状态。复现数据保存在 `audit_counterexample.json`。

新增 `library_m12.guard.RevocableReader`：把合法但相互矛盾的重复观测追加为反证，撤销当前假设的证明依赖，设置失败状态，再报告异常。此后全域证书为 False，预测调用也被阻止。对全部 256 张三变量表分别加入一条矛盾观测，均撤销；一致重复则保留证书。

原 M8 文件和旧结果原样保留，便于核验。**适配器是新入口，不会自动替换直接实例化旧 PolynomialReader 的程序。** 实际使用旧读者的调用方应改用此适配器；不能因为新测试通过就声称旧类已经原地修复。

## 结论三：存储、身份、算法和证书必须分开

记录带有 Queen/Worker 标签，不等于程序自己识别了主体。原实现对来源格式和引用合法性的检查有用，但没有认证现实来源，也不是抵抗同进程恶意 Python 的沙箱。

所有版本的满分主要发生在明确的有限族中；次数、变量、候选机制、稳定性和独立噪声等条件不能在摘要中省略。完整日志打平说明目前没有特殊空间介质的独立优势。关系图、索引或递归引用是否节省总计算，需要另测，不能用查询数替代 CPU/内存成本。

M13–M15 将“自身”限定为实际归属并绑定在当前 Queen 上的可变判断程序；当前元审查核、任务合同、记录通道和验证器继续作为外部可信基础。这一边界从正文、测试到 README 保持一致。

## 结论四：交付组织可以继续使用，但必须保留分期含义

`LIBRARY_THEORY.md` 是旧版正文，不因文件名简短就自动变成最新版。新 README 指向 v0.4，并链接旧版；不覆写旧论文的论证。M0–M15 是研究阶段编号，不是十五项普遍成立的科学定律。

M8 测试位于 `library_m8/tests.py`，只运行默认的 `tests/` 发现入口不会自动包含它。本轮分别执行旧 28 项和新 24 项，不将两个数字混成全部历史回归测试。新运行器内置本轮测试、合同摘要检查和完整实验入口。

首次完整新实验尝试达到执行工具的单次时间上限，未产生成绩档。之后仅缓存不可变输入构造、复用四格干预中的相同 Worker 数据，结果协议未变。首份完整记录以及加入合同哈希硬检查后的最终记录均保留；没有据成绩改变任务、故障族或挑战集。运行细节见 `M12_M15_EXECUTION.md`。
