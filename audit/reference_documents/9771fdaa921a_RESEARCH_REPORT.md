# Library 研究总报告

## 结论

研究推进至 M7，形成“版本—目标约束的再观察”理论原型。证据来自实际执行的确定性世界、有限全集穷举、独立实现交叉核对与明确假设下的手工证明。它支持一个较窄但可检验的主张：系统能够围绕当前修改目标维护证据、补充区分性观察、更新跨版本适用关系，并拒绝没有共同可接受修改的情况。

没有建立“图书馆必然产生自主进化”“三维空间优于序列记忆”“递归观察本身产生智能”或“这是一套全球首创理论”。普通完整日志对照打平，模型遗漏和目标冲突的反例都完整保留。

## 从历史切片走到修改依据

单纯保存“过去发生了什么”不足以解释一次修改。系统还要回答：当时的证据现在是否有效？它要求解决的究竟是内部错误还是外部任务？不同解释是否仍要求不同的行动？当前修改会破坏哪些已有成功？

M1 自动留下 Worker 行动、观察反馈和 Queen 判断，再让 Queen 读取自己上一次判断。M2 把当前不确定性组织成候选解释与可选校正，信息不足时自动选择下一次探测。M3 实际应用固定范围的校正并验证，而不是在日志中假装改变已经发生。

M4 显示来源可信和模型覆盖不能省略。M5 显示旧经验不能无条件搬到新版。M6 提炼共同修改集合和查询下界。M7 则把此前仅检查内部目标的合同放回自然环境，发现局部修复与旧成功有时确实冲突。

## 主要证据

| 检验 | 实际结果 | 能支持什么 |
| --- | --- | --- |
| 256 个有限世界的校正诊断 | 每世界 4 次观察；保留 16 个兼容解释；校正全部正确 | 不必完整识别自己即可确定目标所需的修改 |
| 完整参数归因 | 每世界 8 次观察，256/256 正确 | 修复充分性与完整归因不同 |
| 查询子集穷举 | 全部 65,536 个子集；最小校正 4、完整归因 8 | 该查询接口下的条件下界 |
| 随机干预对照 | 64 个种子 × 256 世界；全部最终正确；平均 8.171875 次 | 固定策略与随机策略的有限成本对照，不是自然样本显著性 |
| 普通完整日志对照 | 全部世界与 Library 逐项打平 | 当前没有存储形式的独立优势 |
| 内部校正及独立挑战 | 256/256；192 个非零修改、64 个无需改变 | 已知线性族、环境中和、有限修改下可形成闭环 |
| 3,072 次版本变化 | 适用历史保留：修复平均新增 1.5 次、归因 2 次；重学为 4 与 8 | 已知变化范围下保留未变约束有效 |
| 自然环境审计 | 平均改善 48、下降 48、不变 160；144 个出现旧成功退化 | 内部正确不等于整体进化 |
| 目标兼容性穷举 | 144 个世界没有满足两个目标的允许校正；证书接受 112 | 冲突有时来自目标与修改范围，不是搜索不足 |

所有比例属于明示有限族，不外推到现实机器人或通用智能。查询更少不等于 CPU、内存或总计算更少；完整枚举假说本身不可扩展。

## 理论原型

理论正文见 [LIBRARY_THEORY.md](LIBRARY_THEORY.md)。核心对象是非空兼容解释集合 H(v,E) 与固定合同 C 下的共同修改集合：

$$K(v,E,C)=\bigcap_{h\in H(v,E)}A_C(h).$$

在模型、来源、干预和执行假设成立时，K 非空等价于存在当前证据能够保证满足合同的修改。完整自我画像不是必要条件。相反，若可用查询无法区分的世界没有共同修改，仅增加重读次数就不够。

跨版本保留采用未变化坐标的关系约束，而不是复制旧参数。目标审计进一步给出这个二值模型中的精确冲突条件：内部净错误 r 与环境错误 e 同时非零时，唯一内部完美校正无法保持每个原有自然成功。

这些基础条件与已有主动诊断、等价类/决策区域识别重叠。当前候选贡献是把再观察、版本适用性与目标冲突组合成可追踪、可拒绝的修改依据，并给出该实例的成本与冲突分类；全球原创性和跨任务优势尚未确立。

## 没有隐藏的反证

仅被动回放的 256 个世界全部保留多种校正；干预来源标签交换使 192 个世界错误归因；候选族之外只在组合情境触发的故障，使 256 个世界错误接受后在挑战中失败；直接合并新版与旧参数产生 3,072 次不一致。诊断器没有自动扩充模型族，也没有自主发现未知变化位置。

M7 的 144 个拒绝不是把失败剔除：它们连独立模拟器枚举所有允许修改也无可行解。接受的 112 个中 64 个是保持不变，只有 48 个非零修改；不能把 112 都叫作新进化。

## 实现与复现

主代码 `library_experiments.py`，运行入口 `run_m1_m6.py`、`run_m7.py`。新增测试 `tests/test_m1_m7.py` 共 23 项，验证入口 `tools/verify.py`。本轮使用 CPython 3.13.5，亲自执行：

```bash
python3 -m unittest discover -s tests -p 'test_m1_m7.py' -v
python3 run_m1_m6.py
python3 run_m7.py
python3 -O run_m1_m6.py
python3 -O run_m7.py
python3 tools/verify.py
```

新增测试全部通过，0 失败、0 错误、0 跳过。普通与优化模式结果内容摘要一致。M0 旧文件保留，本轮没有重新执行 M0 测试，不把它算入新增执行数量。

最终主实验内容 SHA-256：`2025e1a1dd74be20bbee4d9405c5300f6bd419c4696231fada2e201bb408dd6c`。

最终 M7 内容 SHA-256：`3a4ee0892983324963ff36777cd811e14b0634218605d2224c050663793dfc95`。

`results/evidence_bundle.tar.xz` 保存本轮四份原始 JSON，包含最终两份以及打包修正前两份；`results/evidence_manifest.json` 列明每个成员摘要。主摘要中 `.json.gz` 路径是重新运行时生成的位置；仓库交付时同名未压缩 JSON 放在该证据包内，验证器支持两种读取方式。

原记录含 256 个主世界的观察、修改与成本，64 个随机种子的逐世界成本及可复现轨迹摘要，3,072 个版本变化记录，完整自动再观察示例及 M7 每世界的目标审计。不是只保存成功总数。

## 实验记录的来源与修正

M1–M6 的合同和协议在实现前单独提交。M7 为主实验之后登记的探索性审计，不能冒充最初预注册的未见成绩；其合同中旧摘要字符串没有在本次所见远端树中提供相应原档，本报告不以它为运行证据。所有结论使用本轮实际执行并保存的数据。

本轮首份实际主记录为 `5b3dec285404eb30bbab2eae078dbc30c3576e55c5b38e42a5580cc5d980a515`，首份 M7 记录为 `cdd469ec6da3adb22d8363fbb8307d21d6f29a80c82208897eb0fc28db803ed8`。交付检查发现运行器枚举全部根目录 Python 文件会把原有 M0 入口意外纳入摘要，所以改为显式列出本轮三份源文件，再完整重跑。实验策略、任务、阈值及全部数值结果没有改变；修正前原记录仍在证据包中。

验证器还核对当前源码与最终记录中的摘要，防止测试版本与交付版本不一致。接口限制与来源标签是实验约定，不是恶意进程安全隔离或现实真实性认证。

## 下一处真正的不确定性

尚未执行的 M8 应检验变化范围或模型族并非事先已知时，系统能否从反例扩大自己的解释，而不靠设计者直接给新故障名称。之后还需要噪声、有限预算、连续多轮修改与非线性独立任务。这些没有被本轮低维结果解决，也没有在会话结束后后台运行。
