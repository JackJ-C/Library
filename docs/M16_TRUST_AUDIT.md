# M16：最终目标与残余可信边界

## 审查结论

本轮不再把“有限原型通过”作为三个最终目标的同义词。目标仍然是整套 Queen 自主审查、未知机制开放式修复及全球原创性；M16–M20 是针对这些目标的进一步实验和查新，不是预设目标已经成立。

实际运行旧 `tools/verify_m12_m15.py`，成功核验原档 `f1fa512b3cd23bb37c195304dc551b646534ecb2959c1d12ae136a10fcb604dd`；另重跑旧 `library_m12.tests` 的24项测试全部通过。验证旧档不是重新执行2304次旧世界；M0–M11的完整实验亦未在本轮重跑。证据日志在 `results/m16_m20/baseline_evidence.log` 与 `baseline_tests.log`。

## “整套”的边界没有消失

| 部分 | M17是否直接注入故障 | 是否产生实际修订 | 仍需信任什么 |
| --- | --- | --- | --- |
| 任务调用 `decide` | 是 | 复制已获同伴行为支持的函数 | 测试任务和调用运行时 |
| 证据读取 `read` | 是 | 是 | 输入记录真实、时期标记真实 |
| 合成 `generate` | 是 | 是 | 原有正确合成器至少有可靠副本 |
| 验证 `validate` | 是 | 是 | 外部验证题的答案正确 |
| 审查 `audit` | 是 | 是 | 其他单元的多数审查可靠 |
| 调度 `schedule` | 是 | 是 | 外部协议仍会收集并执行调度结果 |
| `probe`行为测试定义和实际采样 | 否，固定 | 否 | 不能用自己的错误答案替代外部参照 |
| `recover`外层流程、`quorum`及安装器 | 否，固定 | 否 | 收票、来源登记、快照和实际写入符合约定 |
| 解释器、编译模板、操作系统和资源限制 | 否 | 否 | 正确执行；不是恶意代码安全沙箱 |

四个单元均可以成为坏单元，不存在某一个永久免疫的单元。但是**单元外仍有固定协议**。因此本轮没有证明“可信基础被消除”，也没有量化证明可信代码规模比M15更小。把`audit`这一函数命名为全部审查机制，会再次犯此前同名部件的错误。

## 实现与合同的差异必须显式保留

合同的理论假设包括单元隔离和来源可信。本轮实现的是同一 Python 进程中的四个逻辑对象，只对指定槽位作错误注入，不实现进程隔离、硬件隔离、签名或恶意单元限制。一个恶意函数可破坏其他对象的情形并未被主实验覆盖。来源注册表仅防止在当前接口中使用未注册名字；不能把字符串身份当成密码学来源认证。

合同中的候选批准程序由可损`validate`承担，但最终批准协议`quorum`没有被自修。M19对其上下文检查做攻击样例，而不是让系统自行重新发明这一协议。安装器破坏使用独立失败样例，结果确实失败。

## 总体科研解释

M17扩展了可恢复的实际程序槽位，并通过同伴证据恢复损坏的合成与审查函数。M18生成新的任务表达式，但元合成算法仍是复制恢复的原算法。这两条进展可以组成端到端测试，不能合并成“元算法已经无限创新”。

新研究独立放在`library_m16/`，没有自动替换M15的`Queen`、旧适配器或希珀塞莱妮娅主系统；旧源码、记录、合同与PR #1原样保留。默认`tests/`发现入口不会包含全部分期测试，应使用每期明确的运行命令。
