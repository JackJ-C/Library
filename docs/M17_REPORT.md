# M17：审查单元自身损坏后的交叉恢复

## 实验设计

每个单元持有六个真实可调用函数。评估器把其中任意非空子集改为静默错误函数或抛异常函数。外层恢复流程没有故障编号输入；它让不同单元运行相同公开行为测试，收集它们对其他单元的判断，再按目标、版本、证据、候选和槽位核对票决。

每项判断排除目标自身，需要另外三个注册单元中至少两票一致。对于确定异常的槽位，从同伴已通过行为检查的实现中复制函数，保持目标对象不变，并一次性更新版本。普通健康情况不写入。外层调度协议仍然固定；复制不是新元算法生成。

## 实际结果

主覆盖为2种错误模式×4个损坏位置×63种非空槽位组合，共504次，每次最多一个单元损坏。504次全部恢复，正常槽位误改0，漏改0；独立正常对照无修改。128次中，坏单元对自身错误报告全健康，其他单元仍给出足以否定它的证据。

恢复后每次在四个单元上运行43个新身份任务输入，共86688个执行检查正确。这不是86688个独立故障样本；输入范围是同一小任务，不是复杂跨域能力评估。恢复调用成本记录为每案例89次单元函数调用；计数不包括全部树枚举、编译器内部步骤和评估器比较，不能称为总计算最优。

每行记录包含注入状态（仅评估层）、实际改变槽位、旧新函数摘要、供体、正反票来源、未解决项、对象不变与正常绑定保持。完整两类六槽故障例子保存在原档`study.M17.full_examples`。

## 这一步增加了什么证据？

故障确实进入用于合成、验证和审查的函数，而不只是外部世界中的一个叫Queen的数值参数。被修复后，该单元仍然使用这些函数执行后续任务。M18另做96次“六槽同时坏—先恢复—再生成新任务程序”的整合流程，避免只验证一个布尔健康标记。

但故障种类是研究者固定的静默错误和异常，公开探针恰能区分它们。通过有限探针不证明任意潜伏程序都正确。所有健康单元来自相同源码，也不具备统计意义上的错误独立性；主条件是故障局限于一个逻辑单元，而非源码天然多样。

## 条件证明

若任意一个目标坏了，其余三个单元在假设下都健康，能产生一致正确的故障证据。若目标健康，其他三个中最多一个坏，因此至少两个正确赞成。每个被批准的供体在同一可辨识故障族下健康。三个健康调度函数产生相同顺序，固定安装器按照稳定快照复制批准函数，因此全部异常槽位恢复且正常槽位不动。

证明依赖可辨识探针、至少三个健全单元、来源认证和安装器正确。它是特定同步容错协议的直接论证，不是新的共识理论。M19的全部单元同时错误/崩溃、两个虚假来源赞成和安装器破坏都不满足这些条件；实验没有将它们误报为成功。
